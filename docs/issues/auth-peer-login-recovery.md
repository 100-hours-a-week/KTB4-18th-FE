# [BUG] 새 탭의 로그인 세션 복구 및 탭 간 로그아웃 동기화 누락

## 2026-10-20 확정 범위

- 탭 A에서 로그인한 뒤 새 탭 B로 접속하면 B는 기존 refresh 세션을 복구한다. B에서 로그인 API를 다시 호출하지 않는다.
- 어느 탭에서든 로그아웃하면 같은 브라우저 프로필의 모든 탭에서 토큰·보호 화면·연결·캐시를 정리한다. 다른 기기/프로필은 유지한다.
- 다른 계정으로 전환이 성공하면 같은 프로필의 모든 탭에 반영한다. 로그인 성공과 로그아웃 알림을 구분하고 중복·지연 알림 및 늦은 복구 응답을 처리한다.
- 현재 FE fix/auth-tab-session-sync에서 수정하며 기존 아래 보고는 발견 이력으로 보존한다. BE 세션 정책·로그아웃 채팅 이벤트 계약은 별도 의존성이다.

## 이번 완료 조건

- [x] 새 탭의 빈 access token 저장소에서 기존 세션과 같은 sub/sid를 복구한다.
- [x] 로그인 경로로 새 탭 접속 시 복구 후 안전한 원래 경로로 이동한다.
- [x] 중복 알림은 복구를 중단하지 않고 계정 전환은 이전 계정 상태를 제거한다.
- [x] 로그아웃과 진행 중/지연된 복구가 충돌해도 인증이 되살아나지 않는다.
- [x] 같은 프로필 전체 로그아웃·다른 프로필 유지를 실제 브라우저로 확인한다.
- [x] 회귀·빌드·정적 검사와 미검증 범위를 기록한다.

## 이번 구현 결과

FE 변경·회귀·브라우저 프로토콜 검증을 완료했다. 실제 운영 인증 검증·배포·코드 리뷰는 별도다. 자세한 결과는 ../verification/auth-tab-session-sync.md를 따른다. 아래 원인/계획 체크박스는 이전 발견 기록으로 보존한다.

## 요약

- 사용자 보고: 한 탭에서 이메일·비밀번호로 로그인한 뒤 다른 탭에서 로그인하면 원래 탭의 로그인이 풀린다.
- 현재 상태: 원인 확인·수정 중. 브라우저 버전·운영 영향 범위·최초 발생 시각·우선순위는 확인하지 않았다.
- 기대 결과: 같은 브라우저의 여러 탭이 로그인 상태를 함께 유지한다.

## 재현 정보

1. 같은 브라우저의 탭 A에서 이메일·비밀번호로 로그인한다.
2. 탭 B에서 같은 계정으로 로그인한다.
3. 탭 A의 인증 상태와 보호 화면 이동을 확인한다.

## 원인과 작업 범위

- 프론트엔드가 로그인 성공·로그아웃을 같은 알림으로 처리하고 기존 탭에 AUTH_EXPIRED를 보낸다.
- storage와 BroadcastChannel의 중복 알림도 복구 중 인증 generation을 다시 변경할 수 있다.
- 실제 로그인은 BE에서 기존 브라우저 세션을 교체하므로 이전 토큰 유지로 우회하지 않고 현재 refresh 쿠키로 복구해야 한다.
- 로그인 성공 알림과 로그아웃·기존 형식의 알림을 구분하고 동일 epoch는 한 번만 처리한다.
- 모의 로그인 API·인증 정책·BE 세션 발급·로그아웃 이벤트 계약은 변경하지 않는다.

- [ ] 같은 알림이 중복돼도 진행 중 복구를 취소하지 않는다.
