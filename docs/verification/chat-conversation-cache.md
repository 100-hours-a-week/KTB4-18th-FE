# 같은 탭의 지역별 이전 대화 복원

[FE #140](https://github.com/100-hours-a-week/KTB4-18th-FE/issues/140).
FE #136의 현재 참여 복구와 별개로 이전에 목록에 반영한 메시지를 복원한다.

## 저장과 복원

- `sessionStorage`의 `meomuneum:chat-conversations:v1`에 계정과 지역별 메시지를 저장한다.
  같은 계정·지역이더라도 방 ID가 바뀌면 이전 캐시를 사용하지 않는다.
- 서버에서 수신해 실제 대화 목록에 추가한 MESSAGE/ACK와 완료된 복구 결과만 저장한다.
  미전송 입력·pending 원문·토큰·view·membership·cursor·부재 메시지는 캐시에 저장하지 않는다.
  저장 필드는 message_id에 대응하는 서버 메시지 필드만 허용한다. 마스킹 본문을 그대로 저장한다.
- 서버 created_at부터24시간이 지난 메시지를 제외하고, message_id 오름차순으로 중복 제거한
  최근200개를 유지한다. 저장·복원·live/recovery 병합·화면 상태 갱신에 같은 제한을 적용한다.
  재열람으로 만료를 연장하지 않는다. 활성 화면은 가장 이른 만료에 타이머로 정리한다.
  비활성 지역의 만료 데이터도 다음 읽기/쓰기에 정리한다.
- 앱 내 내비게이션 이동·같은 지역 재입장에는 현재 탭 캐시를 복원한다.
  새로고침/문서 history 복원에서도 sessionStorage의 유효 메시지만 사용한다.
- sessionStorage는 opener나 브라우저에 의해 복제될 수 있으므로 앱 최초 로드에 Navigation Timing을 확인한다.
  fresh document navigation에서는 상속된 캐시를 비우고 reload/back_forward에서만 디스크 캐시를 읽는다.
  처음에 채팅을 열지 않고 새 탭을 새로고침해도 상속된 메시지가 뒤늦게 나타나지 않는다.
  Navigation Timing을 확인할 수 없으면 저장 캐시 복원을 생략하고 현재 문서에서 시작한다.
  일반 문서 URL 새 탐색은 캐시를 비우며, 앱 내 SPA 이동과 구분한다.
- localStorage·다른 기기 저장소·메시지 BroadcastChannel 동기화는 사용하지 않는다.

## 참여 문맥과 인증

- 새 참여에서 캐시는 표시용으로만 복원한다. 기존 view/last_message_id/cursor를 연결에 전달하지 않는다.
  서버는 새 실제 구독부터 열람 권한을 부여하며 부재 기간을 조회해서 채우지 않는다.
- 복원한 대화와 다시 입장한 이후 대화에 구분 안내선을 표시한다. 복원만으로 전송을 활성화하지 않는다.
  새 연결·복구 완료 여부는 기존 FE #136 흐름을 따른다.
- 로그아웃·인증 제거·계정 전환 시작에는 모든 지역 캐시를 정리한다. 같은 계정의 JWT 갱신은 유지한다.
  다른 계정 토큰이 설치되면 캐시를 비우고 기존 채팅 소유자를 종료해 화면·복구 문맥도 제거한다.
- 캐시 세대를 사용해 인증 전환 전의 늦은 메시지 저장이 새 계정 캐시를 덮어쓰지 못하게 한다.
  늦게 성공한 이전 계정의 REST 입장은 원래 토큰으로 퇴장 처리하며 새 연결을 만들지 않는다.

## 오류와 호환성

- 손상 JSON·알 수 없는 버전·잘못된 메시지/방 스키마는 캐시를 폐기한다.
  토큰이나 서버 메시지 원문을 로그에 출력하지 않는다.
- 저장소 접근 거부·quota 오류가 현재 채팅·인증 전환을 실패시키지 않는다.
  저장에 실패하면 해당 저장 키 제거를 시도하고 현재 문서 메모리의 제한된 메시지만 유지한다.
  브라우저가 삭제까지 거부하면 물리 삭제를 보장할 수 없지만 현재 문서 복원·쓰기 권한은 즉시 무효화한다.
- 캐시는 서버 권한 증명이 아니며 로컬 저장소 조작을 서버의 과거 조회 권한으로 사용하지 않는다.
- 백엔드 API/DB 계약은 변경하지 않는다. FE #136 배포 전제는 동일하다.
  구버전 FE로 복귀하면 새 저장 키를 읽지 않으며, 다음 새 문서 탐색/탭 종료 때 브라우저 세션 범위로 정리된다.

## 검증

- 자동화: 계정/지역/방 분리, refresh 복원, 상속 캐시 폐기, 정확히24시간 경계,
  200개·중복 제한, 인증 정리 후 늦은 저장, 손상 JSON/버전/필드, quota/삭제 오류,
  미전송 원문 제외, 새 참여와 이전 cache 분리, 퇴장 후 메시지 제외,
  활성 화면 만료, JWT 갱신/계정 전환과 이전 연결 종료, 늦은 입장 정리, 안내 접근성.
- 실제 브라우저: 개발 서버의 `tests/fixtures/chatCache.html`에서 합성 메시지를 저장하고
  새로고침 후1개 복원, 일반 새 탭0개, rel=opener 새 탭0개 및 그 탭 재로딩0개,
  계정 전환0개, 저장 후 로그아웃 정리0개를 확인했다.
- fixture는 캐시 모듈과 실제 sessionStorage/Navigation Timing만 사용한다.
  운영 로그인·백엔드 서버·사용자 메시지를 사용하지 않는다. 실제 서비스 화면의 서버 재입장,
  네이티브 브라우저 복제/닫은 탭 복원·다른 기기까지 수동 검증한 결과는 아니다.
- 최초 기존 메시지 테스트5건은 과거 고정 fixture가24시간 범위 밖이라 실패했다.
  테스트 시각을 fixture 기준으로 고정하고 만료 경계 테스트를 추가했다.
  새 테스트 TypeScript 오류2건은 테스트의 this 타입과 추가 필드 입력 타입을 보완했다.
