# 기기별 지역 이동 연동

F2는 현재 탭의 인증 세션에서 위치를 판정하고 같은 세션으로 입장한다.
작업 브랜치는 `feature/chat-device-region-transition`, 시작 HEAD는 F1 PR #175가 병합된 `ad6845d`다. BE B5와 연동한다.

## 동작

- 기존 10분 주기와 15초 재확인, GPS 정확도·재시도·권한 오류 안내를 유지한다.
- 두 판정의 지역이 다르거나 위치 확인이 실패하면 기존 방을 유지한다.
- 이동 후보·15초 대기·최종 판정·대기 중인 입장 작업마다 시작한 사용자/sid와 현재 참여를 확인한다.
- 인증 세션이 바뀌면 이전 판정으로 새 세션을 입장·퇴장시키지 않는다. 화면 이탈과 종료 신호도 처리한다.
- 이동 확정 후 현재 참여의 연결과 복구를 정리하고 퇴장한 다음, 최종 판정 토큰으로 새 방에 입장한다. 조회 실패·만석이면 이전 방으로 자동 복귀하지 않는다.
- 다른 기기에 지역을 전파하는 전역 저장소나 broadcast를 추가하지 않는다. 서버가 현재 sid의 참여만 종료한다. 같은 sid의 다른 탭은 기존 membership 종료 알림을 받으며 자동 입장 정책을 새로 만들지 않는다.

`chatSessionFetch`는 위치 판정/입장을 시작한 토큰의 sub/sid를 고정한다.
같은 sid의 최신 토큰을 선택하고 인증 모듈의 current-token 전송 경로를 사용한다.
전송 전에 동일 sid의 토큰 갱신이 경합한 경우에만 한 번 재시도한다. 이미 전송한 변경 요청은 자동 재전송하지 않는다.
이 경로는 다른 sid로 refresh 후 요청을 다시 보내지 않으며, 서버의 401은 기존 API 오류 안내로 처리한다.

공통 API의 일반 호출은 기존 authenticatedFetch를 유지한다. 위치 판정과 채팅 입장에 선택한 소유 토큰을 전달할 수 있게 했다.
요청 JSON·응답 타입·환경 변수는 바꾸지 않는다. BE는 위치 토큰 자체의 sid와 입장의 JWT sid도 비교한다.
클라이언트의 JWT 파싱은 지연 작업의 소유권을 구분하는 용도이며 서명 검증은 서버가 담당한다.

## 검증 결과

- 이동 성공 회귀를 포함한 최종 전체 Vitest 486개 통과, 실서버 환경이 필요한 3개 제외. chatParticipation 25개 단독 재검증도 모두 통과했다.
- Prettier·ESLint·채팅 검증용 TypeScript 구성 통과.
- 전체 tsc/build는 기존 loginQueueApi 모듈 누락과 App의 authCapabilityMessage/LoginPageProps 불일치로 실패한다. 해당 인증 화면을 이번 작업에 섞어 수정하지 않았다.
- 신규 세션 고정 테스트에서 다른 sid 전송 차단, 같은 sid 최신 토큰 선택, 전송 전 갱신 경합 1회 재시도, 전송 후 재시도 금지를 확인했다.
- 참여 상태 테스트에서 후보/대기/최종 판정 도중 sid 변경 시 이동 금지, 기존 정책의 조회 실패·판정 실패·경계 오차, 최종 확인 토큰으로 이동 성공을 확인했다.
- 초기 기존 테스트는 새 소유 토큰 인자와 인증 문맥 fixture가 없어 실패했다. fixture/인자 단정을 갱신해 관련 100개와 최종 참여 25개 재검증이 통과했다.
- BE 실제 서버에서 `chatRegionTransition.integration.test.ts`를 별도로 실행해 실제 API wrapper의 위치 판정·세션별 입장·지연 요청 차단·다른 sid 증명 거절·이동 후 남은 참여 ID 보존을 확인했다. 일반 Vitest 실행의 조건부 제외와 구분한다.
- 같은 BE에서 기존 실제 FE 복구 연동도 통과했다. 인증 저장소와 전송 대역을 사용한 Node 클라이언트 검증이며 실제 휴대전화 두 대·브라우저 쿠키 동기화·물리 GPS 이동을 검증한 결과는 아니다.

B5를 먼저 적용한다. 음악 기록·기기별 로그아웃·탭별 퇴장·계정 이력 복원은 변경하지 않았다.
제품 배포·push·PR 등록·외부 기획 원본 수정은 수행하지 않았다.
