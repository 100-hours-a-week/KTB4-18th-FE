# F3 탭별 퇴장 연동

입장 응답의 `view_session_id`를 참여 상태에 보관하고 첫 CONNECT부터 전송한다. 화면 이탈·pagehide·unmount의 기존 stop 경로는 해당 식별자로 DELETE를 보낸다. 연결 전 이탈이나 지연된 입장 성공도 같은 식별자로 정리하므로 같은 sid의 다른 탭을 종료하지 않는다. stop 중복 호출은 퇴장 요청을 늘리지 않으며, 종료 후 비동기 복구 응답을 화면에 반영하지 않는다.

인증 문맥은 기존대로 sub/sid를 고정한다. 같은 sid의 최신 토큰은 사용할 수 있고 다른 sid·계정으로 바뀐 뒤에는 이전 참여의 퇴장을 전송하지 않는다. 토큰·view·복구 cursor는 대화 캐시에 저장하지 않는다. 기존 지역별 실제 수신 메시지 캐시는 유지한다.

지역 이동 확정은 확인한 위치 토큰을 별도 `region-departures` 경로로 보낸다. 단순 탭 퇴장과 달리 같은 기기의 모든 탭을 이전 방에서 종료하는 기존 B5/F2 정책을 유지한다. 최초 연결 전 실패의 30초 제한은 view 발급 여부가 아닌 실제 CHAT_READY 수신 여부로 판단한다.

BE B6와 함께 적용해야 한다. 새 FE는 view가 없는 구형 입장 응답을 거절하며, 구형 FE의 view 없는 DELETE는 새 BE에서 400이다. API 계약 변경과 참여 흐름 변경을 별도 커밋으로 분리한다.

## 검증

- 채팅 관련 단위·컴포넌트·API 101개 통과, 실서버 조건부 3개 제외. 실제 BE 실행에서는 신규 탭 퇴장과 기존 복구·지역 이동의 조건부 연동도 모두 실행·통과했다.
- 실제 FE 서비스 두 인스턴스와 MySQL·WebSocket 서버를 연결해 같은 sid의 view 분리, 한 탭 stop 후 다른 탭 전송, 중복 stop, 입장 응답 지연 후 정리, 종료 view 조회 거절을 확인했다. 실제 모바일 브라우저·물리 GPS·운영 쿠키 검증은 수행하지 않았다.
- 전체 빌드·ESLint 통과. 전체 테스트 최종 실행은 587개 통과·기존 이미지 추천 1개 실패·실서버 조건부 4개 제외다. 이미지 추천 실패는 수정 전 HEAD 86a7e99의 격리 사본에서도 재현했다. 첫 전체 실행의 음악 검색 타이밍 실패는 단독 및 최종 전체 실행에서 재현되지 않았다.
- 전체 Prettier에는 기존 인증 관련 6개 파일 위반이 있다. 이번 변경 파일은 개별 검사한다. 기존 인증 포맷을 이 작업에 포함하지 않는다.
- 브라우저 종료 시 keepalive 전송은 최선의 시도다. 서버에 도달하지 않은 요청은 일시 단절의 30초 유예가 적용된다.

- 기존 다중 클라이언트 통합 harness도 current-token 전송 대역과 탭별 종료 기대값으로 정렬했다. 같은 sid의 writer는 퇴장 후에도 전송하고, 새 view의 재입장에서 부재 메시지는 제외된다. BE process 검증 5개 통과·실브라우저 조건부 1개 제외에 이 시나리오를 포함한다.
- 전체 회귀와 변경 전 재현 결과 JSON은 `node_modules/.tmp/f3-tab-verification/`에 보존했다. 추가 harness 변경 뒤 전용 TypeScript·ESLint·Prettier 검사도 통과했다.
