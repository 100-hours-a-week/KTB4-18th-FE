# 채팅 인증 세션 문맥 연동

F1 / B1, 2026-10-16. 범위는 현재 인증 세션과 채팅 연결의 연결이다.

- access JWT의 sub/sid를 로컬 소유권 비교에 사용한다. JWT 서명과 실제 권한 판정은 서버 책임이다.
- CONNECT의 `auth_session_id`에 sid를 전달한다. 토큰/식별자를 URL에 넣거나 별도 저장·탭 간 방송하지 않는다.
- 같은 sub/sid의 토큰 갱신은 기존 view와 재연결 흐름을 유지한다.
- sub 또는 sid 변경/인증 제거는 이전 연결·복구·버퍼·리스너를 정리한다. 이전 인증 상태에서 시작한 입장 응답과 실시간·복구 지연 응답은 새 상태에 반영하지 않는다.
- 입장 응답이 늦게 성공하면 기존 방식대로 원래 토큰으로 정리하며 새 인증으로 연결하지 않는다. 탭별 퇴장 API나 로그아웃 전파 정책 자체는 변경하지 않는다.
- sid 누락/잘못된 형식이면 연결을 준비하지 않고 재로그인 안내를 제공한다. 이미 발급된 정상 sid는 토큰 갱신으로 바뀌지 않는다.
- 현재 기기 경계의 기술적 식별은 기존 인증 세션이다. 물리 기기를 추적하거나 다른 브라우저를 자동으로 묶지 않는다.

## 검증

- 원본 format:check·lint·전체478개 및 verify:chat:types 통과, 실제 서버 의존2개는 일반 실행에서 제외했다.
- 새 테스트는 sid/계정 분리·동일 세션 토큰 갱신·동일 계정 세션 교체·refresh 대기 중 인증 변경·복구 중 인증 제거·입장 지연 응답 폐기·hook 종료를 포함한다.
- BE 임시 검증 사본과 실제 MySQL/HTTP/STOMP로 기존 FE 통합 테스트를 별도 실행하여 통과했다. 사본에서 선행 BE 컴파일 오류만 분리했으며 실제 원본 BE 전체 빌드 성공을 뜻하지 않는다.
- 원본 build는 선행 인증 변경의 누락 loginQueueApi 모듈과 LoginPageProps의 authCapabilityMessage 불일치로 실패한다. 이번 변경에서 해당 코드는 수정하지 않았다.
- 실제 로그인·물리 기기 UI·기기별 로그아웃·지역 이동·과거 이력 공유·서버 재시작은 이번 완료 범위가 아니다.

## 적용

- BE 계약: `meomuneum-backend/api/chat-auth-session.md` 및 `chat-auth-session.schema.json`.
- membership·정원·퇴장·로그아웃·계정 이력 공유는 후속 작업에서 변경한다. 기존 local cache 만료·계정 정리를 유지한다.
- 선행 인증 빌드 오류를 해결한 뒤 원본 build와 실제 로그인 기반 연결을 다시 검증한다. GitHub 이슈 번호는 미확인이고 PR·push·배포는 수행하지 않았다.
