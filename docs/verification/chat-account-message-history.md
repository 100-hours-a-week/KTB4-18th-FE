# F6 서버 참여 이력 기반 대화 복원

## 사용자 흐름

GPS 입장과 실제 구독의 CHAT_READY 이후 탭 복구를 진행하고 mode=history의 계정·방 이력을 조회한다.
최대50개씩 최신200개까지 읽고 페이지 snapshot과 ID 내림차순 진행을 확인한다.
모든 필요한 페이지를 받은 뒤 서버 이력으로 로컬 캐시/화면을 대체하고 탭 복구·버퍼의 live/ACK를 ID로 병합한다.
화면·캐시는 기존24시간·최신200개 제한과 마스킹된 서버 필드만 저장하는 규칙을 유지한다.
빈 서버 결과도 캐시를 비운다. 현재 탭이 처음 보는 다른 기기의 허용 대화도 복원한다.
현재 탭만 부재하고 같은 계정의 다른 탭이 참여한 구간도 제공한다. 모든 기기가 부재한 구간은 서버가 제외한다.
계정 history gap을 사용하고 탭 recovery의 gap을 추가해 잘못된 부재를 표시하지 않는다.

## 권한과 실패

이력 요청은 입장한 sub/sid의 chatSessionFetch로 전송한다. 같은 sid 토큰 회전은 허용하고 다른 sid로 전송하지 않는다.
페이지 로드 중 전송을 막고 live/ACK를 버퍼링한다. 실패 시 부분 결과를 적용하지 않고 수동 복구 재시도를 제공한다.
취소·퇴장·계정/세션 변경 뒤 도착한 응답은 폐기한다. 재연결 때도 이력을 새로 조회해 서버 권한을 다시 반영한다.
인증·쿠키·탭 간 로그아웃 동기화는 수정하지 않는다. B7 인증 담당자 이벤트 의존성도 유지한다.
새 레이아웃 없이 기존 복구 상태·이전 대화 안내·전송 차단을 사용한다.

## 계약·적용

BE B9의 history/by-client-id 계정 참여 이력과 현재JWT sid/view 소유권 검사가 선행해야 한다.
기존 REST 성공 응답 구조와 recovery/CHAT_READY는 유지한다. history cursor의 asOf는 opaque 서명 문맥이다.
서버 이력은 항상 권한 근거이고 캐시는 로드 중 임시 표시만 담당한다.
B9 먼저 적용 후 F6를 적용한다. 구형BE+신형FE 조합은 계정 이력 복원을 제공하지 못하므로 지원하지 않는다.
롤백은 양쪽을 함께 고려하고 현재 연결/cursor를 폐기해 새로 시작한다.
DB·환경 변수·의존성·인증 모듈·공동 재생 변경은 없다.
